# Remnawave autoinstall

Автонастройка серверов Remnawave на **чистой Ubuntu/Debian**:

- **нода** — обновление пакетов, SSH, firewall, fail2ban, Nginx (self-steal) + HAProxy (SNI) + Let's Encrypt, BBR и оптимизация сети, Remnanode в Docker;
- **панель** — Remnawave Panel + страница подписки за nginx с HTTPS и (по желанию) секретной ссылкой для входа;
- **обновления** панели, страницы подписки и ноды одним пунктом меню;
- **проверка и исправление** последствий старых версий скрипта.

## Запуск на пустом сервере

От root (`sudo -i`):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/KimHarada/Remnawave-autoinstall-scriots/main/menu.sh)
```

Скрипт сам скачает тулкит в `/opt/dorik-toolkit`, поставит недостающие пакеты и покажет меню
с **состоянием сервера** (что установлено и работает). Повторный запуск безопасен: уже сделанное пропускается.

Перед установкой направьте A-записи доменов на IP сервера — иначе сертификаты не выпустятся
(скрипт проверит DNS заранее и скажет, что не так).

## Меню

| Пункт | Что делает |
|---|---|
| **1. Полная настройка** | Определяет, что уже стоит, предлагает исправить следы старых версий, задаёт вопросы один раз и проходит этапы с прогресс-баром. После **каждого** этапа проверяет результат |
| **2. Панель Remnawave** | Установка панели, обновление (с бэкапом БД), установка и обновление страницы подписки, ссылка для входа |
| **3. Обновить ноду** | Скачивает свежий образ `remnawave/node`, пересоздаёт контейнер только если образ изменился, проверяет порт и логи |
| **4. Закрыть лишние порты и укрепить сервер** | Аудит всех слушающих портов, удаление лишних правил firewall, отключение ненужных служб, укрепление ядра и SSH (см. ниже) |
| **5. Проверка и исправление** | Находит проблемы от старых версий скрипта и правит их с вашего согласия |
| **6. Дополнительно** | Экстренное восстановление SSH, только BBR, только Nginx+HAProxy, только Remnanode |

Все пункты доступны и без меню: `menu.sh --full | --harden | --ports | --doctor | --update-node | --panel-install | --panel-update | --sub | --sub-update | --bbr | --status`.

## Закрытие лишних портов и укрепление

Идёт отдельным этапом полной настройки и отдельным пунктом меню (`--harden`; `--ports` — только показать порты).

1. **Аудит.** Таблица всех слушающих сокетов: *нужный* / *закрыт firewall* / *ОТКРЫТ, лишний* / *Docker: открыт мимо ufw*.
   Нужные порты: SSH, 80/443, порт ноды, 443/udp для Hysteria2, порты самой ноды (inbound'ы задаёт панель).
2. **Firewall.** Политика «входящие закрыты», фильтрация IPv6, удаление **всех** лишних allow-правил (диапазоны, «всё с адреса»,
   старые порты). SSH-порт открывается до любых действий, поэтому отрезать себя нельзя. Список правил показывается перед удалением.
3. **Службы.** Если снаружи слушают `rpcbind`, `avahi`, `cups`, `snmpd`, `smbd`, `vsftpd`, `apache2` и подобные — они отключаются
   (в логе подсказка, как вернуть). Незнакомые процессы **не трогаются**, только показываются.
4. **Ядро и сеть.** Без ICMP-редиректов и source-routing, SYN-cookies, мягкий rp_filter, `kptr_restrict`, `dmesg_restrict`,
   запрет unprivileged BPF; блокировка неиспользуемых модулей `dccp`, `sctp`, `rds`, `tipc`.
5. **SSH.** `MaxAuthTries 3`, `LoginGraceTime 30`, без X11 и пустых паролей (файл `sshd_config.d/00-dorik-hardening.conf`,
   проверка `sshd -t`, применение через reload). Вход по паролю отключается **только** по вашему согласию и только если есть ключи;
   повторный запуск пароль не возвращает (`SSH_ENABLE_PASSWORD=1` — вернуть осознанно).
6. **Автообновления безопасности** (`unattended-upgrades`).

Свои порты оставить: `HARDEN_KEEP_PORTS="8443/tcp 9000"` (без `/proto` — tcp и udp). Если вы открывали в ufw порт под
дополнительный inbound ноды — добавьте его туда же, иначе правило будет удалено как лишнее.

**Docker.** Порты, опубликованные контейнерами на все интерфейсы (`-p 9999:80`), **обходят ufw**. Скрипт их находит и сообщает,
но сам не переписывает чужие контейнеры: публикуйте на `127.0.0.1` (`-p 127.0.0.1:9999:80`). Контейнеры панели и страницы подписки
уже слушают только localhost, нода работает в сети хоста и подчиняется ufw.

## Полная настройка: этапы

| Этап | Что происходит и что проверяется |
|---|---|
| Базовые пакеты | `curl ufw dnsutils cron psmisc …`; ждёт `unattended-upgrades`, чинит прерванный dpkg |
| Обновление | `apt full-upgrade` без вопросов про конфиги. *Проверка:* dpkg и зависимости целы |
| SSH + firewall | Смена порта с откатом при неудаче, ufw, fail2ban (`backend=systemd`), часовой пояс, ребут в 04:00. *Проверка:* порт sshd, правила ufw, jail fail2ban, cron |
| Nginx + HAProxy | Заглушка (случайная для каждого сервера), SNI-маршрутизация, Certbot с автопродлением. *Проверка:* службы, заглушка, сертификаты |
| BBR | BBR + `fq` и настройка сети под прокси (буферы для QUIC, backlog, лимиты файлов). *Проверка:* активный congestion control |
| Remnanode | Docker, compose (`NET_ADMIN`, ulimits, ротация логов, права 600), Hysteria2. *Проверка:* контейнер, порт, сертификат внутри, логи |

## Панель Remnawave

Пункт 2 → «Установить панель»: спросит домен панели (и, по желанию, домен страницы подписки), сгенерирует секреты,
поднимет панель из **официального compose Remnawave** (скачивается при установке — новые версии не требуют правки скрипта),
выпустит сертификат и настроит nginx. На выходе — ссылка для входа вида `https://panel.example.com/?k1a2b3c4=…`
(без неё панель закрыта; встроенная выдача подписок `/api/sub/` остаётся публичной).

Страница подписки ставится рядом с панелью и требует API-токен (панель → Настройки → API-токены) — его скрипт попросит.
Обновление панели делает `pg_dump` в `/opt/remnawave/backups`, показывает изменения образов, подтягивает новые параметры `.env`
и при неудаче печатает команды отката.

Панель нужно ставить на **отдельный сервер**: на сервере с нодой порт 443 занят HAProxy.

## Запуск без вопросов (cloud-init / автоматизация)

```bash
export ASSUME_YES=1 ROLE=1 NEW_SSH_PORT=22 \
       DOMAIN_TCP=tcp.example.com DOMAIN_GRPC=grpc.example.com DOMAIN_XHTTP=xhttp.example.com \
       DOMAIN_HY2=hy2.example.com NODE_PORT=3001 SECRET_KEY='...' PANEL_IP=203.0.113.10
bash <(curl -fsSL https://raw.githubusercontent.com/KimHarada/Remnawave-autoinstall-scriots/main/menu.sh) --full
```

Панель: `ASSUME_YES=1 PANEL_DOMAIN=panel.example.com SUB_DOMAIN=sub.example.com … menu.sh --panel-install`,
страница подписки: `REMNAWAVE_API_TOKEN=… menu.sh --sub`.

Ответы на «да/нет» в этом режиме берутся по умолчанию. Необязательные переменные:
`LE_EMAIL` (почта для Let's Encrypt), `DORIK_TZ` (часовой пояс, по умолчанию `Asia/Irkutsk`),
`DECOY_NAME` (конкретная заглушка из `decoys/`, например `geese.zip`), `NO_COLOR=1` (без цветов).

Подробный лог каждого запуска пишется в `/var/log/dorik/`.

## Проверки

Перед установкой скрипт проверяет окружение и останавливается на критичном: нет systemd, мало места на диске, не работает DNS
или HTTPS до GitHub/Docker Hub, порты 80/443 заняты чужим процессом. Про мягкие проблемы (мало памяти, часы не синхронизированы,
контейнерная виртуализация, неизвестная версия ОС) только предупреждает.

После каждого этапа идёт проверка результата, а в конце — независимая перепроверка всего сервера «врачом».
Дополнительно: SSH и порт ноды не могут совпадать друг с другом и с 80/443; SSH-порт должен быть открыт в ufw для всех;
после выпуска сертификата проверяется автопродление (`certbot renew --dry-run`); `SECRET_KEY` проверяется на формат
(base64 от JSON, как в панели).

Переменные: `PREFLIGHT_SKIP=1` — пропустить предполётную проверку; `DORIK_IGNORE=time_sync,net_tuning` — не считать
перечисленные замечания «врача» проблемами; `SSH_DISABLE_PASSWORD=1` — в режиме без вопросов отключить вход по паролю
(только если есть ключи); `HARDEN_KEEP_PORTS` — порты, которые укрепление не закрывает.

## Что проверено

Полные прогоны на **чистых** образах Ubuntu 22.04.5 и 24.04.5 (в них нет `ufw`, `dig`, Docker): роль ноды с настоящим
`SECRET_KEY`, панель с настоящим админом и API-токеном, страница подписки, обновления, повторный запуск (идемпотентность),
смена SSH-порта с откатом, SSH под `ssh.socket`, ожидание блокировки apt, «врач» на искусственно сломанном сервере.
Ubuntu 26.04 — отдельные прогоны. Debian 11/12 в списке поддерживаемых, но **не проверялся**.
Выпуск сертификатов в живом Let's Encrypt в тестах заменялся самоподписанными (у тестовых доменов нет DNS).

## Требования

Ubuntu 22.04 / 24.04 (проверено) или Debian 11/12 (не проверялось), root, доступ в интернет,
порты 80/443 свободны на время выпуска сертификатов.
